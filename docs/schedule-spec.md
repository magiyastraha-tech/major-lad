# «Мажорный лад Расписание» — как устроено

Вторая программа в этом же репозитории: отдельный exe, отдельная папка
`Data` рядом с ним. Исходный текст задачи — `docs/schedule-spec-source.txt`,
этот файл фиксирует принятые решения.

## Файлы программы

Рядом с exe: только `Data` (данные); звуки лежат внутри неё, в
`Data/Sound`. В версиях до 0.3.0 звуки были в папке `Sound` рядом с exe —
при первом запуске 0.3.0 программа переносит их в `Data/Sound` сама (уже
существующие файлы не перезаписывает, старую папку убирает, только если
она опустела).

Данные — одна база SQLite `Data/Мажорный лад Расписание.db` (таблицы
`students`, `subscriptions`, `lessons`, `payments`, `blocks`). Каждое
изменение пишется транзакцией, поэтому сбой посреди записи не оставляет
половину таблицы.

Рядом с базой программа сама поддерживает текстовые файлы — их удобно
читать диктором и открывать в блокноте:

- `Data/Students/` — на каждого ученика файл `Имя Фамилия.txt`: имя и
  фамилия, телефон, онлайн или очно, тип занятия (вокал, акустическая
  гитара и т. д.), действующий абонемент (когда куплен, с какого числа
  действует, сколько уроков всего, сколько проведено и осталось,
  стоимость), список законченных абонементов и ближайший урок.
- `Data/Проведённые уроки.txt` — проведённые уроки, новые сверху:
  «Алёна Пупкина, 20.11.2026, уроки 5 из 8.». Урок, привязанный к
  абонементу, считается внутри своего абонемента; у каждого абонемента
  счётчик идёт от 1 до его размера.
- `Data/расписание.txt` — уроки на месяц вперёд от сегодняшнего дня
  (не от даты покупки абонемента), отменённые не попадают.
- `Data/Исключения.txt` — дни и часы, когда уроков нет, с сегодняшнего
  дня и дальше: «2 декабря, среда: весь день без уроков. Причина:
  болею.» Причину видит только преподаватель.

Эти файлы — зеркало базы, а не второй источник правды. Программа
перезаписывает их сама после каждого сохранения и при запуске, ручные
правки в них не читаются обратно. Свои файлы в `Data/Students/`
программа не трогает: удаляет она только те `.txt`, которые сама же
создала (их первая строка — служебная шапка).

- При первом запуске версии с базой программа сама переносит данные из
  старых `Ученики.txt`, `Абонементы.txt`, `Расписание.txt`,
  `Журнал оплат.txt`, а сами файлы убирает в `Data/Архив старой версии`
  (не удаляет).
- Каждый запуск перед открытием базы делает копию в `Data/Резерв`
  (одна на день, хранятся последние 14).
- F9 выгружает все данные читаемым текстом в `Data/Выгрузка.txt` — для
  диктора и для проверки глазами.
- `Data/Настройки.txt` — сочетания клавиш, которые ты настроил сам.

## Звуки

Папка `Data/Sound`: `Напоминание.wav`, `Начало урока.wav`,
`Конец урока.wav`. При первом запуске программа создаёт их сама
(высокие, средние и низкие тона — их трудно перепутать). Чтобы поставить
свой звук, положи файл с тем же именем поверх — программа не
перезаписывает уже существующие. Что за что отвечает — в
`Data/Sound/Как заменить звуки.txt`. Если звук не проигрался, программа
подаёт системный писк, чтобы напоминание не осталось немым.

Громкость сигналов — в настройках, раздел «Звуки» (0–100 процентов, ноль
значит «без звука»). У системного проигрывателя своей громкости нет,
поэтому программа делает приглушённую копию WAV во временной папке;
исходный файл в `Data/Sound` не меняется. Когда срабатывает напоминание,
сначала звучит сигнал, и только когда он отзвучал, говорит диктор —
одновременно они перебивают друг друга.

## Код

| Файл | Что делает |
| --- | --- |
| `schedapp/paths.py` | папка программы, `Data`, `Data/Sound`, старое место звуков |
| `schedapp/dates.py` | даты и время словами для диктора |
| `schedapp/store.py` | модели, база данных, перенос из старых txt |
| `schedapp/mirror.py` | текстовые файлы `Students/`, `Проведённые уроки.txt`, `расписание.txt` |
| `schedapp/uikit.py` | `Announcer` (объявления диктору), запись клавиш единой строкой |
| `schedapp/settings.py` | сочетания клавиш и громкость: `Настройки.txt` |
| `schedapp/sounds.py` | звуки: создание, громкость, проигрывание, длина |
| `schedapp/updater.py` | проверка обновлений, докачка, подмена exe и перезапуск |
| `schedapp/reminders.py` | напоминания и вопросы об уроке |
| `schedapp/ui.py` | окна: список учеников, расписание, карточка, формы, настройки |
| `schedule_main.py` | точка входа, из неё собирается exe |

## Логика урока

- На главном окне три кнопки: «Добавить ученика», «Редактировать ученика»
  и «Удалить ученика». Правка и удаление сначала спрашивают, кого именно:
  список учеников, выбор стрелками, «Дальше». Удаление дополнительно
  переспрашивает по имени. Вместе с учеником пропадают его абонементы и
  уроки, включая уроки в расписании; оплаты в журнале остаются — деньги
  были настоящими. Переименование ученика переносит за ним абонементы,
  уроки и оплаты.
- Счётчик уроков — это число проведённых уроков, записанных в абонемент,
  а не отдельная цифра. При запуске программа сверяет счётчик с уроками:
  если уроков не внесено, будет «0 из 8», даже когда раньше стояло
  «4 из 8». Старые проведённые уроки без привязки программа привязывает к
  абонементу, который действовал в их день. Абонемент, где уроки кончились,
  закрывается сам; закрывшийся именно из-за нехватки уроков снова
  становится действующим, если урок удалили.
- Напоминания: за день, за час, за 10 минут до начала.
- В начале урока — «идёт ли урок?». Ответ «да» — через 40 минут вопрос
  «прошёл ли урок?». Нет ответа — повтор через час.
- «Прошёл» — урок помечается `проведён`, счётчик абонемента +1, сумма идёт
  в журнал оплат. «Нет» — урок помечается `отменён`.
- Разовый урок прибавляется кнопкой «Добавить разовый урок» — в карточке
  ученика или на вкладке законченных абонементов. Это одно занятие со своей
  ценой: уроков не считаем, в историю он попадает сразу, действующий
  абонемент не закрывает. Оплата ложится в журнал отдельной строкой,
  поэтому попадает в F5. Так же устроен пробный урок, только он без оплаты.
- Покупка абонемента при заведении ученика тоже пишется в журнал.
- Абонемент хранит две даты: когда куплен и с какого числа действует.
  Отсчёт уроков идёт от даты начала, а не от даты покупки: человек платит
  иногда заранее, иногда с опозданием. При заведении ученика, при первом
  пополнении, при новом абонементе и при вписывании старого обе даты
  выбираются в форме.
- Карточка ученика (F2) — две вкладки: «Действующий абонемент» и
  «Законченные абонементы». В действующей — остаток уроков и кнопки
  «Добавить проведённый урок», «Редактировать урок», «Удалить урок» и
  «Добавить новый абонемент». В истории — список законченных абонементов
  и записей о пробном и разовом уроках, выбор нужного и те же кнопки, плюс
  «Добавить законченный абонемент», «Добавить пробный урок» и «Добавить
  разовый урок».
- «Заработок за месяц» (F5) считает по сумме, записанной в самом уроке или
  абонементе, а не по старой строке журнала. Поменял цену разового урока с
  1600 на 1100 — и в месяце, и в журнале будет 1100: парная запись журнала
  правится вместе с записью урока. Абонементы берут сумму из своей
  стоимости, услуги и прочие поступления — из журнала оплат, пробные
  уроки не считаются вовсе. Парная строка журнала узнаётся по ученику и
  виду записи, даже если её дата разошлась с датой покупки, поэтому одна
  и та же сумма не прибавится дважды; старые дубли таких строк тоже
  считаются один раз. Если абонемент удалён, а его строка оплаты осталась,
  деньги не пропадают: она идёт в законченные.
- «Редактировать урок» показывает список проведённых уроков абонемента:
  выбери урок, потом поправь дату и при желании время. Дата в будущем не
  принимается, на дату, где в этом абонементе уже есть урок, второй не
  встанет.
- «Удалить урок» показывает тот же список и убирает выбранный урок.
  Счётчик абонемента возвращается на один назад, урок пропадает из файла
  «Проведённые уроки»; если абонемент закрылся именно потому, что уроки
  кончились, он снова становится действующим. Законченный вручную старый
  абонемент так не открывается. Деньги в журнале оплат не меняются —
  оплата была настоящей.
- В окне редактирования абонемента (дата покупки, начало) есть кнопка
  «Редактировать расписание»: открывается тот же выбор дней и часов, что
  при добавлении, только уже отмеченный как было. Снял галочку с дня,
  поставил на другой, поменял время, сохранил — будущие непроведённые
  уроки ученика перестраиваются по новому расписанию. Прошедшие и
  проведённые остаются как есть: история назад не переписывается. Урок,
  попавший на исключение, переносится на неделю вперёд по тому же дню, и
  так пока не найдётся свободное место.
- «Добавить новый абонемент» заодно записывает расписание: в том же окне
  отмечены дни недели и время уроков, и программа ставит уроки на четыре
  недели вперёд, начиная с сегодняшнего дня или с даты начала абонемента
  (что позже). Галочка «Заодно записать уроки по расписанию» включена по
  умолчанию; у законченного абонемента расписания нет — уроки там уже
  прошли. Отдельная кнопка «Добавить уроки по расписанию» остаётся на
  случай, когда расписание меняется посреди абонемента: она только
  записывает уроки, не трогая абонемент и оплату.
- «Добавить законченный абонемент» заводит старый абонемент для истории:
  покупка, начало, уроки, стоимость. Оплата за него в журнал не идёт —
  деньги пришли раньше, в кассу текущего месяца они не попадают.
  «Добавить новый абонемент» делает абонемент действующим, прежний сам
  уходит в историю; оплата пишется в журнал.
- «Добавить проведённый урок» открывает окно с датой: по умолчанию —
  день после последнего отмеченного урока этого абонемента (или его
  первый день). Один урок за одно окно; счётчик прибавляется сам, в файле
  «Проведённые уроки» урок встаёт по дате. Так вписываются старые уроки и
  дописываются пропущенные. Урок на ту же дату дважды в один абонемент не
  запишется — программа скажет об этом.
- Формат и тип занятия у урока по умолчанию берутся из карточки ученика.
- Окно не закрывается, а уходит в трей: напоминания продолжают работать.

## Исключения и сетка записи

- Вкладка «Исключения» — дни и часы, когда уроков нет: уехал, заболел,
  день рождения. «Добавить день» закрывает день целиком, «Добавить
  время» — промежуток «с … до …». Причина необязательна, хранится в
  базе (таблица `blocks`) и показывается только преподавателю; в
  `Исключения.txt` она тоже есть, а ученику она не показывается.
  Исключение можно добавить и не уходя со вкладки «Ученики» — кнопкой
  «Добавить исключение уроков»: она спрашивает дату и по умолчанию
  закрывает день целиком, а переключатель «Весь день» снимается, если
  закрыть нужно только часы.
- Вкладка без записей прячется, чтобы не мешалась в переключении. Если
  открыть её сочетанием клавиш, программа скажет, что она сейчас пуста и
  спрятана. Стрелок прокрутки под полосой вкладок нет.
- Один урок — 45 минут, перерыв — 15 минут: сетка записи идёт шагом в
  час. Очно — с 08:00 до 21:00, онлайн — с 08:00 до 23:00, время
  пермское. Занятость часа видна по урокам со статусом `ожидается`;
  исключение проверяется через `Store.is_blocked(day, time)` — это
  заготовка для бота записи, который появится позже.
- Облачная копия хранит таблицу `blocks` вместе с остальными. Копия от
  прежней версии (без этой таблицы) берётся через «Взять данные из
  копии»: `sync.restore` дочитывает схему `Store.ensure_schema()` до
  `load()`, поэтому старая копия не ломает восстановление.

## Обновления

Кнопка «Проверить обновления» в настройках: программа спрашивает релизы
GitHub, находит последний с меткой `schedule-v…` и файлом
`MajorLad-Schedule.exe`, скачивает с докачкой и перезапускается уже
новой версией. Проценты проговариваются диктором каждые 10%, затем
«скачано, устанавливаю», затем «программа перезапускается». Проверка
идёт в отдельном потоке, окно не подвисает.

Запущенный exe на Windows не отдаёт сам себя: подменить его «на месте»
нельзя. Поэтому установка идёт в два шага: скачанная версия ложится
рядом с программой под именем «Мажорный лад Расписание.new.exe»,
запускается установщиком и ждёт, пока программа закроется. Установщик
дожидается выхода, убирает старый файл в «...old.exe» и встаёт на его
место — когда файл уже никто не держит. Обе временные копии программа
убирает сама при следующем запуске, `Data` установка не трогает.

Если установить не удалось (нет прав на запись в папку программы,
оборвалась сеть) — программа говорит об ошибке словами и остаётся
работать; данные в `Data` при этом не затрагиваются. Отдельно
проверяется, что в папку программы вообще можно писать: если нет,
программа прямо предлагает перенести её вместе с папкой `Data` в свою
папку вроде «Документы».

## Настройки и горячие клавиши

Ctrl+P (или кнопка «Настройки», или пункт в меню в трее) открывает окно,
устроенное как в первой программе: разделы идут сверху вниз, без вкладок,
длинное — прокручивается стрелками.

- «Общее» — версия программы, «Проверить обновления», «Выгрузить данные
  в текст», «Открыть папку Данные».
- «Звуки» — громкость сигналов напоминаний от 0 до 100 процентов и кнопка
  «Проверить звук», чтобы услышать выбранную громкость не выходя из
  настроек. Ноль выключает сигналы совсем (системного писка при этом нет).
  «Сбросить по умолчанию» возвращает и громкость 80 процентов.
- «Сочетания клавиш» — строка-кнопка на каждую команду: карточка ученика,
  уроки на сегодня, уроки на завтра, заработок за месяц, выгрузка данных,
  настройки. Нажал на строку — открылось окно «Назначить клавиши»: нажми
  нужное сочетание, и оно встанет. Escape оставляет как было, Backspace
  убирает клавишу совсем. «Сохранить» — и клавиша работает сразу, без
  перезапуска. Одна и та же клавиша на две команды не встанет: программа
  скажет, где она уже занята. «Сбросить по умолчанию» возвращает F2–F5,
  F9, Ctrl+P.
- Ниже — раздел «Кнопки на вкладках»: на клавиши назначаются кнопки
  главного окна (добавить ученика, разовый урок, абонемент, услугу,
  исключение и так далее). По умолчанию клавиш у них нет.
- Дальше — раздел «Вкладки»: переключение на любую из девяти вкладок.
  По умолчанию Ctrl вместе с цифрой на цифровом блоке: 1 ученики,
  2 расписание, 3 действующие абонементы, 4 законченные, 5 разовые и
  пробные, 6 услуги, 7 уведомления, 8 исключения, 9 будущие абонементы.
  Цифровой блок ловит фильтр событий главного окна. Цифру программа
  узнаёт по скан-коду клавиши Windows — он у блока свой и от Num Lock не
  зависит; если скан-код не дошёл, по пометке цифрового блока Qt, а в
  последнюю очередь по самой цифре. Поэтому сочетание работает при любом
  положении Num Lock, в том числе когда Qt не помечает клавишу блока. У
  назначения на блок есть и запасной ярлык с той же цифрой верхнего
  ряда. Голая цифра блока без Ctrl остаётся набором числа в полях —
  командой считаются только сочетания с Ctrl, Alt или Meta.

Сочетания клавиш и громкость хранятся в `Data/Настройки.txt` (громкость —
строкой `volume = 80`) и переживают обновления и перезапуски. Если в старом файле на настройках стоит F10, программа один
раз сама ставит Ctrl+P; твой собственный выбор она не трогает. Горячие
клавиши — родные ярлыки Qt на всё приложение, поэтому работают из любого
окна и в любой раскладке. Пока окно настроек открыто, они выключены —
чтобы назначение новой клавиши не запускало команду.
